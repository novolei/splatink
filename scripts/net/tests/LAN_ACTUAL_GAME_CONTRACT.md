# Two-process actual Game ENet contract

This is an opt-in fixture around **production InkGame, InkActor, InkStage, weapons, controller, HUD, results and room teardown** on both endpoints. Unlike `lan_process_contract.gd`, it reports `actual_game=true`. It runs the requested role only and uses an isolated LAN UDP port; it does not discover services, contact a relay, change production protocol, modify Mini Tanks, or start another engine process.

Use the owning host's serialized Godot wrapper, or a dedicated PC build snapshot containing this test and its production dependencies. Start host first, guest second, with a shared unique run identifier. The host binds ENet's default wildcard listener (`0.0.0.0`). Both endpoints can be headless; this fixture makes no GPU performance claims.

```text
--headless --path <dedicated-Splatink-snapshot>
--script res://scripts/net/tests/lan_actual_game_contract.gd --
--lan-game-role=host
--lan-game-host=<host-LAN-IP>
--lan-game-port=27898
--lan-game-run=<same-unique-run>
--lan-game-output=<absolute-writable-host-report.json>
--nonpersistent --benchmark-background
```

On the other endpoint set `--lan-game-role=guest` and a separate output path. The default report path is `user://lan-actual-game/<run>-<role>.json`; the 120-second watchdog is adjustable with `--lan-game-timeout=40..240`. The test sets Game and UI nonpersistent **before** `_ready`, independently of supplied arguments. It leaves UI fixture mode off, so normal room loading, wipes and cleanup execute. User settings and progression are neither loaded nor saved.

Round one starts eight real source-physics actors (two humans and six host-owned bots), checks real baked Tidewater and live HUD, and waits for the authoritative intro-to-playing/follow-camera transition. Each local controller receives a real `move_forward` action. The test injects a deterministic splat through production `Game.paint_splat` and a hit through production `Actor.damage`; remote Stage CPU ink, owner HP and remote snapshots must agree. To isolate networking from unpredictable attacks, the fixture replaces Bot AI commands with a quiet `InkBots` subclass while real Actor ticks/physics remain active. It does not claim that every shot, animation or rendered effect was verified.

The host calls production `_show_results` to assemble all eight result rows, award memory XP, show the actual results/podium and publish the result. Both peers wait the source 12-second room-return deadline, retain the same room, show the real Lobby, and clear old match actors. Memory progression advances once for this completed round, while persistence remains disabled. A second real match starts; after both reach playing, the host deliberately closes ENet and cleans its local Game. The guest must receive one abrupt-disconnect signal, run the deferred production cleanup, return to Online with HUD hidden and mouse visible, dispose old Stage/actors, and preserve post-round-one XP. Reentrant leave/stale close must produce no second abort.

The first-round checkpoint also records `native_framing`: sent native frame count, budget error flag, inbox completed/rejected/expired/pending counters, buffered metadata and the actual remote actor timeline. Both endpoints must send without a budget error and remain bounded. The guest must reconstruct fragmented host frames (seven host-owned actors); the host receives the guest's ordinary one-human tick, so it proves the small receive path through its real timeline instead of requiring an invented oversized guest payload. These counters are evidence of the tested transport branch, not proof that no unreliable packet was ever lost.

Collect **both reports and both engine logs**. The first actual Windows ↔ macOS run (`pc20261004a`) passed its 36 host / 35 guest assertions, but is **not accepted as clean**: the guest log reported a removed Actor transform query during normal room return, and the Mac host reported an ENet snapshot larger than its MTU. Root detached the follow-camera target before actor removal; bounded native tick framing addressed oversized packets.

The second two-machine run (`pc20261004b`) is accepted for the stated functional scope: `shots/pc-lan-actual-macos-host-fixed.json` passed 39 checks and `shots/pc-lan-actual-windows-guest-fixed.json` passed 38, with no failed checks. Root checked both engine logs and reported no ERROR/WARNING; the Windows log is retained as `shots/pc-lan-actual-windows-guest-fixed.stdout`. Both reports have `actual_game=true`, `real_enet=true`, `single_process=false`, GO=2 and normal end=1. Guest received the result and exactly one second-round abort; intentional host leave produced zero aborts. Both persistence hashes remained unchanged. Guest reconstructed 52 host frames with 20 expired pending frames, zero pending/rejected/buffered entries at the checkpoint and no budget error. Host exercised the ordinary one-human small packet path. The guest's 130 sent frames measure the opposite direction, so 52/130 is not a packet-loss ratio.

Subsequent plain telemetry/native-animation runs `pc20261004c` and `pc20261004e` passed their functional JSON assertions (host45/guest44) but the Mac stdout reported two ObjectDB instances at shutdown; they are **not accepted as fully clean**. The verbose `pc20261004d` run did not reproduce that object warning and did report orphan StringNames. Root later reproduced the same two-object Mac diagnostic from ordinary menu shutdown with no network; it is not specific to LAN or compression, and the precise cause remains unproven. Keep stdout separate from `--log-file` output when auditing this issue. Current fixture code opts into bounded per-sender source/arrival gap samples and reports sent small/fragmented/part totals alongside timeout/capacity/duplicate/stale counters.

The production transport remains plain by default. An explicit `--native-tick-zstd` on **both** endpoints selects a bounded compressed native candidate, documented in [NATIVE_ZSTD_CONTRACT.md](NATIVE_ZSTD_CONTRACT.md). With that flag the guest must receive actual compressed host frames, the host must send compressed frames and receive the guest's ordinary small ticks, and both endpoints must report bounded authorizations/decode output and clear authorization on match return/connection teardown. Without the flag the original fragment/small assertions remain required. The fixture's separately measured ZSTD timings include entropy encoding/decoding only, while the full six-field production envelope determines wire-budget estimates; guard and transport costs are not included in those timing samples.

The fresh candidate `pc20261004z1` passed **host50/guest49 functional assertions**, including eight actual native MM avatars on both match starts. Reports are `shots/pc-lan-zstd-{macos-host,windows-guest}.json` with matching log/stdout captures. The host sent 131 single-packet compressed ticks and the guest completed 57 without partial-frame capacity eviction, rejection, pending frames or timeout; the reverse path received 110 ordinary ticks. Host/guest sampling windows differ. Host-to-guest source/arrival gap p95 was **932/934 ms**, so this run does not establish smooth delivery or a latency improvement. Windows diagnostics were clean; Mac stdout retained the separate two-object shutdown warning. Both the cadence cause and shutdown cause remain unresolved, and compression remains default OFF.

With `--native-locomotion-mm` on both endpoints, the fixture additionally requires all eight production avatars to report the actual native MMAnimationLibrary provider, `native_mm_active=1`, a 234-pose weapon bucket, an empty native error and an upper-body mask at both match starts. The first-round playing checkpoint also requires every avatar to have executed native queries over 234 poses. The second-round start deliberately checks provider activation without requiring a query before intro has advanced. Reports retain per-actor evidence under `native_locomotion.checkpoints`; these conditional assertions observe the real avatars and do not create substitute matchers or change combat/lifecycle timing. The subsequent plain runs established this functional native-provider scope, subject to the unresolved Mac shutdown diagnostic above.

The earlier Windows ↔ macOS ProbeGame run passed, but remains a separate `actual_game=false` result. This fixture does not cover relay/WAN interoperability, host migration, late joining, GPU performance, arbitrary combat, foreign ghost-storm kills, all player timing races or smoothness under sustained loss.
