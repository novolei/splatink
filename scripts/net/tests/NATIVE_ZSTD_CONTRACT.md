# Opt-in native ENet tick compression candidate

`--native-tick-zstd` selects the production ZSTD codec/inbox in `InkNetwork` for native ENet rooms. The default remains `InkNativeTickCodec.split` and the existing plain inbox. Both endpoints must supply the flag for this development experiment. There is no capability negotiation in this candidate: a plain endpoint explicitly rejects compressed envelopes. WebSocket/WSS relay packets and the original source tick layout remain unchanged.

Ordinary small source ticks stay byte-for-byte uncompressed. Larger ticks are encoded from the complete `var_to_bytes(tick)` representation, including all original actor fields, stats, clock and Boss metadata. One compressed envelope is chosen only when its entire serialized RPC argument payload plus the existing 64-byte reserve and ten-character peer identity fits 1200 bytes. It advertises version, sequence, original size, raw/compressed hashes and compressed bytes. The decoder removes the envelope before source replication or host forwarding. If compression cannot fit, unsupported values occur, or the original tick exceeds the 64 KiB compression cap, the encoder returns exactly the existing bounded fragment packets.

The actual RPC callback obtains its sender ID from `multiplayer.get_remote_sender_id()`. The host replaces a claimed identity with this authenticated peer ID and requires membership in its room. A guest accepts a known room sender only through peer 1, the authenticated host. Only after these checks does the compressed inbox authorize that canonical positive 31-bit identity. At most eight authorized senders exist. The envelope hashes detect corruption; they are not an authentication mechanism.

Before native decompression the receiver checks envelope types/version, packet budget, sequence and source timestamp, hashes, a dictionary-free single-segment ZSTD frame with exact advertised length, bounded block structure and no trailing/concatenated frames. Decompressed byte output is bounded at 65536 bytes. A finite, object-free Variant preflight limits depth to 32 and walked Variant nodes to 8192 before `bytes_to_var`; packed numeric components do not count as separate Variant nodes, and each packed string array additionally has its own count limit and the shared byte bound. The decoded dictionary, unique actor identities, source header and canonical serialized round-trip must match. Small, fragmented and compressed completed ticks share timestamp ordering, and compressed/fragmented ticks share sequence ordering. Incomplete or invalid frames cannot update source replication. The fallback retains the original fragment receiver rather than changing its wire format or acceptance rules.

Peer disconnect clears its authorization, ordering, cadence and partial frames. Room return/leave clears all such state, so the next match or connection can use a fresh source clock/sequence. Diagnostic inbox totals follow the existing inbox's counter lifetime; source/arrival history and authorization do not. `native_tick_metrics()` reports separate `sent_small`, `sent_fragmented`, `sent_compressed` and `received_compressed` counters plus `zstd_enabled`. `inbox.completed` continues to count reconstructed fragmented frames; `inbox.compressed_completed` counts lossless compressed frames.

This fixture uses the production codec/guards and real `InkNetwork` selection, authenticated-sender checks and leave lifecycle. It covers exact ticks, ordinary packets, incompressible/cap fallback, reverse fragment assembly, ordering transitions, duplicate/loss/lifecycle limits, malformed envelopes, bounded advertised sizes, noncanonical senders and malformed Variant structure. It does not open ENet; its report explicitly states `actual_enet=false`, `production_paths=true` and whether the adapter flag was enabled.

Root's fresh import and production-path OFF/ON contracts each passed 141 assertions with zero failures; `shots/pc-native-zstd-off.json/.log` and `shots/pc-native-zstd-on.json/.log` retain the reports. Root checked their engine logs and stdout independently and reported both clean. Largest tested decompressed output was 61616 bytes and largest packet plus reserve was 1200 bytes. The unchanged plain codec passed its original 112 assertions again. These reports still state `actual_enet=false` and `default_enabled=false`; they do not establish actual delivery or performance. The earlier draft123 record remains historical evidence only.

A subsequent read-only compatibility audit found that Godot's [String.append_utf8](https://github.com/godotengine/godot/blob/4.7/core/string/ustring.cpp) strips a leading UTF8 BOM during the [Variant string decoder](https://github.com/godotengine/godot/blob/4.7/core/io/marshalls.cpp). The encoder now performs a bounded, object-disabled decode and validates both dictionary equality and exact re-encoded bytes after preflight, before selecting compression. Noncanonical values select exactly the original plain fragment fallback. This preserves the original fallback's existing decoder behavior; it does not repair Godot's historical string canonicalization in plain transport. Ordinary String/StringName preflight rejects NUL bytes, and packed string elements allow NUL only at their advertised endpoint, so an embedded wire NUL never reaches `bytes_to_var`.

The fixture observes six actual Godot source-value probes (ordinary Unicode, leading BOM, NUL input to the public UTF8 constructor, and the corresponding packed string array cases including encoded terminal NUL), then requires the selected encoder path to match the observed canonical round-trip. It records whether a NUL codepoint/BOM actually survives construction rather than assuming String can store either. Two additional raw Variant probes insert an embedded NUL into ordinary/packed string bytes, require guard/inbox rejection without source-time advancement, and explicitly record `not_attempted_rejected_preflight` instead of calling the decoder on rejected input. A completeness assertion requires all eight probes to finish; stdout must still be checked for script/Unicode diagnostics. The first revised OFF attempt (`shots/pc-native-zstd-canonical-off.log.stdout`) emitted a String.chr(0) Unicode error and an intermediate typed-array runtime error; its JSON `passed` was insufficient and root rejected it. Those diagnostics remain retained.

After the narrow fix, root's OFF and ON production-path contracts each passed **172 assertions with zero failures**, retained in `shots/pc-native-zstd-canonical-fixed-{off,on}.json/.log` and corresponding `.log.stdout` files. Root scanned both logs and stdout for engine/script/Unicode parsing diagnostics and reported them clean. Ordinary Unicode round-tripped canonically; source leading BOM remained stored but round-tripped noncanonically, and the encoder selected the exact original fragment fallback. Godot's public UTF8 constructor truncated the attempted `ink<NUL>wave` input to the three-character `ink` value with no NUL codepoint stored: the subsequent canonical compressed result preserves that actual source value, **not** the original NUL input. Both raw embedded-NUL probes failed preflight, skipped Variant decoding, and were rejected without timeline advancement. The maximum byte output/packet budget remained 61616/1200. These results supersede the earlier 141-check candidate for the new codec paths; `actual_enet=false`, default OFF and actual delivery/performance limits still apply. Encoder canonical decode/re-encode overhead is not included in the earlier raw ZSTD timing samples.

The fresh two-machine candidate `pc20261004z1` used isolated matching snapshots, independent imports, real Windows guest ↔ M2 Max macOS host ENet on port 27898, and both native animation/compression flags. `shots/pc-lan-zstd-macos-host.json` passed **50 functional assertions** and `shots/pc-lan-zstd-windows-guest.json` passed **49**, with zero failed assertions. Both real matches exercised eight native MM providers, original movement/paint/damage, results, room return, second-round disconnect and authorization cleanup. Windows log/stdout were clean. Mac stdout still reported the separate two-object shutdown warning, so the run is not accepted as fully clean.

At the checkpoint the host sent 131 compressed packets for 131 compressed ticks, no fragments and at most one part per tick. The guest completed 57 compressed ticks with zero rejection, stale frames, capacity eviction, pending frames or timeout; its peak decompressed output was 1936 bytes. The reverse path received 110 ordinary guest ticks at the host. Counter windows differ, so these figures are not an exact loss ratio. Estimated complete seven-actor wire payloads decreased from 1508 to 500 bytes, and from 2028 to 584 bytes with stats. Raw ZSTD encode/decode samples remain separate from canonical validation, guard and actual transport costs.

**Delivery cadence was not improved or accepted.** Host-to-guest completed source gaps had median 69 ms, p95 932 ms and maximum 1532 ms; arrival gaps had median 68 ms, p95 934 ms and maximum 1521 ms. The reverse ordinary path had source/arrival p95 85/138 ms. One-packet compression removes partial-frame capacity eviction in this run but does not prove smooth remote playback; the cause of the long delivery gaps remains unproven. Keep the candidate default OFF pending end-to-end cadence investigation.

See [the isolation matrix](../../../docs/macos-headless-shutdown-diagnostic.md). Exact leaked types and a production repair remain unproven. Affected original runs are not accepted as fully clean, and this compression experiment does not hide or claim to repair that separate issue. Engine stdout and the engine log must both be examined even when JSON reports pass.
